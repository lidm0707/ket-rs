# บทเรียน ket-rs: กฎ → ลาเทนต์ → การตัดสินใจ (ไม่ต้องเทรน)

> คู่มือสำหรับการศึกษา อธิบายการคำนวณจาก `examples/rule_latent.rs`
>
> โครงหลังบ้าน (substrate): [katgpt-rs](https://github.com/katopz/katgpt-rs)
> (`katgpt-core` / `katgpt-sense`) — ทุก primitive (`SalienceTriGate`,
> sector projection) import มาจากที่นั้น

---

## 1. ภาพรวม

ket-rs "เข้าใจ" ข้อความได้โดยไม่ต้องเทรน เพราะความหมายถูก*กำหนดด้วยกฎ*
ไม่ได้เรียนรู้จากข้อมูล กฎแต่ละข้อ map cue substring (ตัวอักษร) ไปยัง latent dim
(ตัวเลข) ท่อประมวลผลคือ:

```
ข้อความ ──encode──> [f32; 4] ลาเทนต์ ──argmax──> คลาส ──project+gate──> คำตัดสิน
```

---

## 2. เวกเตอร์ลาเทนต์

`STATE_DIM = 4` (`src/latent.rs`) ตัวอย่างกำหนดความหมายของแต่ละดัชนี:

| ดัชนี | Const       | ความหมาย |
| ----- | ----------- | ------- |
| 0     | `DIM_MEAL`  | หลักฐาน "อาหารปรุงสุก" |
| 1     | `DIM_FRUIT` | หลักฐาน "ผลไม้ดิบ" |
| 2     | `DIM_SWEET` | หลักฐาน "หวาน" |
| 3     | `DIM_HOT`   | หลักฐาน "เสิร์ฟร้อน" |

ทุกค่าเริ่มที่ `0.0` และไม่เกิน `EVIDENCE_MAX` — ดัชนี = ความหมาย เพราะเราตั้งชื่อ
const กำกับเอง ไม่ใช่ embedding ที่โมเดลเรียนรู้เอง

---

## 3. ค่าคงที่: มาตราส่วนที่มนุษย์เลือก

| Const | ค่า | จุดประสงค์ |
| ----- | ----- | --------------- |
| `RULE_HIT` | 0.5 | คะแนนต่อกฎปกติที่ fire; เจอหลักฐานเยอะ = คะแนนสูง |
| `ALERT_HIT` | 2.5 | คะแนนกฎอันตราย เพื่อให้ความเสี่ยงชนะ argmax เสมอ |
| `EVIDENCE_MAX` | 3.0 | เพดานต่อ dim; ทำให้ทุกช่องเทียบกันได้และ gate เสถียร |

สังเกตความสัมพันธ์ `ALERT_HIT + RULE_HIT = EVIDENCE_MAX` (2.5 + 0.5
= 3.0) สัญญาณอันตรายหนึ่งครั้งบวกหลักฐานปกติหนึ่งครั้ง = อิ่มพอดีที่เพดาน
จึงรับประกันว่าความเสี่ยงจะไม่ถูกกลบเกินไป

---

## 4. ขั้นที่ 1 — Encode

`encode()` ตรวจ cue ของทุกกฎด้วย `text.contains(cue)` กฎหนึ่งข้อ fire
ได้แค่ครั้งเดียวแม้เจอหลาย cue (ใช้ `.any()`) กฎที่ fire จะบวกคะแนนเข้า dim ของ
ตัวเองโดย cap ที่ `EVIDENCE_MAX`:

```rust
fn bump(dims: &mut [f32; STATE_DIM], dim: usize, hit: f32) {
    dims[dim] = (dims[dim] + hit).min(EVIDENCE_MAX);
}
```

ตัวอย่าง: `"hot rice and curry"`

| กฎ | cue ที่เจอ | บวกคะแนน |
| ---- | ---------- | ---- |
| `cooked-staple` | `rice`, `curry` (2 cue, fire ครั้งเดียว) | `dims[0] = min(0.0 + 0.5, 3.0) = 0.5` |
| `served-hot` | `hot`, `curry` | `dims[3] = 0.5` |

ผลลัพธ์: `dims = [0.5, 0.0, 0.0, 0.5]`, reasons = `["cooked-staple", "served-hot"]`

ตัวอย่าง: `"a raw sweet banana"`

| กฎ | cue | บวกคะแนน |
| ---- | --- | ---- |
| `raw-fruit` | `banana` | `dims[1] += 0.5` |
| `sweet-profile` | `sweet` | `dims[2] += 0.5` |
| `eaten-raw` | `raw` | `dims[1] += 0.5` → `1.0` |

ผลลัพธ์: `dims = [0.0, 1.0, 0.5, 0.0]`

เหตุผลของคำตอบคือชื่อกฎที่ fire พอดี (อธิบายได้ 100% เพราะเราเขียนกฎเอง)

---

## 5. ขั้นที่ 2 — จัดหมวดด้วย argmax

**argmax** คือ "ตำแหน่งของค่ามากสุด" (ต่างจาก `max` ที่คืนค่า)
`classify()` เทียบเฉพาะช่องคลาส (dim 0, 1):

```rust
let mut best = (Class::Meal, f32::NEG_INFINITY);
for class in Class::ALL {
    let evidence = dims[class.dim()];
    if evidence > best.1 {
        best = (class, evidence);
    }
}
best.0
```

- `dims = [0.5, 0.0]` → argmax = ดัชนี 0 → **Meal**
- `dims = [0.0, 1.0]` → argmax = ดัชนี 1 → **Fruit**

ค่ามากสุดชนะ ถ้าเสมอกันตัวแรกชนะ เพราะใช้ `>` ไม่ใช่ `>=` จุดสำคัญ: ดัชนี = ความหมาย
เพราะเรากำหนดเองว่า dim ไหนคือคลาสอะไร นี่คือสะพานจาก "ตัวเลข" กลับไปเป็น "ความหมาย"

---

## 6. ขั้นที่ 3 — ฉายเข้าเซกเตอร์

`KetScorer::project` (`src/score.rs`) เอา latent ไป dot product กับ
`DIRECTIONS` ที่มนุษย์เขียน (ค่า −1/0/+1 เท่านั้น):

```rust
const DIRECTIONS: [[i8; STATE_DIM]; SECTOR_COUNT] =
    [[1, 0, 0, -1],   // sector 0
     [0, 1, 1, 0],    // sector 1
     [0, 1, 0, 1],    // sector 2
     [-1, 0, 1, 1]];  // sector 3
```

สำหรับ `dims = [0.0, 1.0, 0.5, 0.0]` (banana):

```
sector₀ = (+1)(0.0) + (0)(1.0) + (0)(0.5) + (−1)(0.0) = 0.0
sector₁ = (0)(0.0) + (+1)(1.0) + (+1)(0.5) + (0)(0.0) = 1.5
sector₂ = (0)(0.0) + (+1)(1.0) + (0)(0.5) + (+1)(0.0) = 1.0
sector₃ = (−1)(0.0) + (0)(1.0) + (+1)(0.5) + (+1)(0.0) = 0.5

sectors = [0.0, 1.5, 1.0, 0.5]
```

แต่ละ sector คือมุมมองหนึ่งของสถานะ เช่น sector₁ จะสูงเมื่อ "ผลไม้ + หวาน"
เกิดพร้อมกัน — ได้ภาพรูปแบบแทนการดูคะแนนคลาสดิบ ๆ

## 7. ขั้นที่ 4 — ประตูตัดสิน emit

gate (`SalienceTriGate` จาก
[`katgpt-core`](https://github.com/katopz/katgpt-rs)) เอา dims คูณกับเวกเตอร์ที่ตั้งมือ (`GATE_D_SPEAK = [0.9, 0.1, 0.0, −0.1]`
ลำดับเดียวกับ dims) แล้วผ่าน sigmoid สองชั้น `1/(1+e^(−βx))` เทียบกับ
threshold 0.5 เพื่อเลือก Speak/Delegate/Silent:

```
"hot rice and curry": dot = 0.9(0.5) + 0.1(0) + 0(0) + (−0.1)(0.5) = 0.40
σ(6 × 0.40) = σ(2.4) ≈ 0.917 > 0.5  →  Speak
```

ตัวเลข 0.9/0.1/0.0/−0.1 คือ "ความตั้งใจของผู้เขียน": อาหารปรุงสุกสนับสนุนการพูดมาก
ผลไม้แทบไม่มีผล ความร้อนดันกลับนิดหน่อย ไม่มีสูตรคำนวณพวกนี้ ปรับด้วยมือเหมือนหมุนลูกบิด

---

## 8. ทำไมจึงไม่ต้องเทรน

| | Neural LM (เทรน) | ket-rs (กฎ) |
| --- | --- | --- |
| ที่มาของความหมาย | เรียนจาก corpus มหาศาล | มนุษย์เขียนกฎเอง |
| ตัวเลข ↔ ความหมาย | embedding ที่อ่านไม่ออก | ตั้งชื่อ dim ชัดเจน map ตรง |
| คำที่ไม่รู้จัก | อาจเดาได้ | ไม่เจอ cue = ไม่ fire = ไม่มีความหมาย |

ทุกตัวเลขในระบบเป็น const ที่มนุษย์เขียน นี่คือ trade-off: อธิบายได้
ครบทุกการตัดสินใจและไม่ต้องเทรน แต่ไม่ generalize เกินกว่า cue ที่เขียนไว้
(เช่น "ข้าวผัด" ไม่มี "rice" ก็จัดหมวดไม่ได้)

---

## 9. ลองเล่น

```sh
cargo run --example rule_latent --release
```

ตัวอย่างพิมพ์ latent และ sectors ของทุกข้อความ ลองแก้ `ALERT_HIT`
เป็น `1.0` แล้วดูว่า case ข้าวบูดเริ่มไม่เสถียร หรือเพิ่ม cue ไทย
(`"ข้าว"` → `DIM_MEAL`) เพื่อรู้สึกว่า "การเข้าใจ" ของระบบคือความครอบคลุม
ของกฎที่เราเขียน
